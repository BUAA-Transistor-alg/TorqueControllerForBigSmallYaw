坑（实测踩过，务必注意）：
1) include guard 必须一起前缀化。两个同源仓库改造前的 guard 完全相同（ROBOT_CONTROLLER_H、ROBOT_COMMUNICATION_C_H 等）。如果只改了路径没改 guard，那么同一个编译单元里同时 include tcs/RobotController.h 与 tcbs/RobotController.h 时，第二个会被 guard 静默跳过，不报错、直接用错实现，比链接错误隐蔽得多。
2) C API 头不要放进 C++ 命名空间。它需要能被纯 C 代码 include；extern "C" 只解决链接名，不解决 C++ 命名空间与 C 类型同名问题。
3) OUTPUT_NAME 必须改。只改 target 名不够，两个子模组仍会产出同名 .so。
4) include 目录只暴露一层。否则 include/communication/Protocol.hpp 这类裸路径仍会撞车。
5) 父工程里 cache 变量是全局的（find_library 结果等），要加前缀，否则两个子模组互相覆盖。
6) add_test 名要带前缀，父工程 enable_testing() 后所有子目录的测试名在同一命名空间里。
7) add_subdirectory 友好化：子目录里不要调用 project()、enable_testing()，不要 set(CMAKE_*)、add_compile_options、include_directories 影响父作用域；用 target_* 形式。
8) 本仓库的 MPC/融合滤波算法、协议字节布局、CRC 实现都不允许改；这次改造只动名字。
